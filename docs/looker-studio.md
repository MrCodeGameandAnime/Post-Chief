# Looker Studio saved reports

The private Apps Script Community Connector lives in `root/src/apps/looker-studio/`. Post Chief exposes a versioned, authenticated export contract at `/api/reports/looker/v1/schema`, `/sources` and `/data`. All routes require existing owner authentication or a revocable agent key with only `analytics:read`. They enforce organization boundaries and never read provider credentials or refresh provider reports. Revoking the key in Agent cuts off subsequent connector requests.

## Data contract

Schema v1 is a long-form metric table: provider/account, snapshot ID/collection time, selected source table/entity, period start/end, timezone, currency, native metric, exact raw value, chart number, unit/meaning, value status, coverage and source notice. Supported sources initially include advertising report tables, GA4 native window totals and normalized account snapshot metrics (for example Twitch channel counters). GA4 totals retain their full property-local reporting window; lifetime/current snapshot counters use their UTC collection date. Arbitrary external blog text and provider-specific non-ad tables are not converted into metrics. Existing authenticated JSON report exports retain those full reports.

Choose one source table per data source. Account daily values and campaign window totals are separate; never combine them as a total. API date filtering includes only rows whose entire reporting period lies inside the requested range; it never prorates a campaign total. Snapshot counters are dated at collection in UTC and are not historical engagement changes. Sources use only the latest saved successful report, including a last good report after a collection error; collection timestamp remains visible. Collect fresh reports in Post Chief explicitly.

Missing native counters produce no metric row. Censored values keep their exact string with null chart number. Values beyond the safe 15-significant-digit/JavaScript integer bound remain exact text and have null chart number with `precision_limited`. Google cost micros stay exact in `metric_raw`; the chart number is converted to account currency units, with unit `currency`. Decimal chart values use ordinary IEEE754 precision; exact amounts remain in the raw field. Chart aggregation defaults to NONE. Filter by metric/unit/currency/entity/grain before selecting an intentional aggregation. Coverage/truncation remains part of each row; no conversion attribution or cross-currency calculations inferred.

The API returns at most 4,000 metric rows from one bounded saved snapshot. Source discovery is paginated by 100 accounts; the connector supports up to 1,000 reporting accounts. A larger organization can use the authenticated API directly. Disconnecting a provider stops collection but retains already saved reports; revoking the reporting key prevents future export. Previously extracted Looker data must be removed separately where appropriate.

## Owner deployment (final pass)

1. Host Post Chief at a stable public HTTPS origin first. It must be reachable from Google Apps Script; a local-only address will not work.
2. Create an Apps Script project. Copy `Code.js` into its code editor and use `appsscript.json` as the manifest. Set the manifest logo URL to an actual accessible brand image before deployment; verify the example favicon exists. No connector publication has been performed.
3. Set Script Property `POST_CHIEF_BASE_URL` to the exact HTTPS origin without trailing slash/path. This is controlled by the connector deployer; users cannot redirect authentication headers to another host through data-source configuration. HTTP redirects are disabled.
4. In Post Chief Agent, create a separate key with only `analytics:read`. Keep the key private. Use the connector's **KEY authentication** prompt; never place it in ordinary config fields or report URLs. The script stores it in per-user properties, not shared Script Properties. Revocation remains in Post Chief.
5. Deploy a private Community Connector and open it in Looker Studio using its deployment ID. Grant the Apps Script external-request scope, enter the key, select one saved source, and choose the date range. This deployment ID is generated by Google; there is no fake Connect link or assumed public listing in Post Chief.
6. Confirm account/org isolation, native currency/timezone/raw values, date filtering, saved collection timestamps, chart filters and revoked-key behavior. Refreshes read saved data only. Avoid sharing a report/data source with access to private account reports unless intended; Looker credential/sharing choices may allow viewers to see cached data.

The dashboard's Analytics page identifies the authenticated export contract and key setup; provider authentication and final Apps Script deployment remain owner actions. This is a Community Connector, not a new social account or native Looker REST data-push API.
