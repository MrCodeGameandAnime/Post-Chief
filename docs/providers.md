# Native providers

## TikTok business / Accounts API (Gate 16)

This connection uses the separate TikTok for Business Accounts API grant, not personal Login Kit or advertiser authorization. Set `TIKTOK_BUSINESS_CLIENT_ID`, `TIKTOK_BUSINESS_CLIENT_SECRET` and `TIKTOK_BUSINESS_AUTHORIZATION_URL` in `root/.env`. In the business developer app, register `PUBLIC_URL/api/connections/oauth/tiktok_business/callback/` with its trailing slash, then copy the app-generated **TikTok account holder authorization URL** for that active redirect. The URL must use TikTok's HTTPS authorization endpoint and match the configured client and callback. Post Chief adds owner-bound, single-use state and disables automatic consent bypass. See [Accounts authorization](https://business-api.tiktok.com/portal/docs/accounts-api-authorization/v1.3).

Enable TikTok Accounts access and request the read permissions `user.info.basic`, `user.info.stats`, `user.insights` and `video.list`. The token inspector checks the actual granted permissions and app/account identity before saving a connection. Account access application/review remains part of the final owner pass. App IDs, access tokens and rotating refresh grants stay encrypted; interrupted or unconfirmed renewal requires reconnect. See [token exchange](https://business-api.tiktok.com/portal/docs/obtain-a-short-term-access-token/v1.3) and [renewal](https://business-api.tiktok.com/portal/docs/renew-a-short-term-access-token/v1.3).

In Analytics, collect an account report, inspect its saved history or export authenticated JSON. Lifetime follower/following/likes/public-video counts remain separate from daily profile metrics for the last seven completed UTC dates. Missing dates and values are unavailable; they are never filled with zero. Native daily data can lag 24–48 hours and video views can include organic and paid activity. Analytics must be enabled in the TikTok account. See [profile insights](https://business-api.tiktok.com/portal/docs/get-profile-data-of-a-tiktok-account/v1.3).

Recent post reporting follows at most five pages of twenty public posts. The snapshot includes IDs, up to 500 caption characters (explicitly marked when shortened), native counters and any returned media/ad flags. Post counters are lifetime, not the profile date window; posts may include ads-only public posts. Pagination limits and partial post failures are explicit. No media download, comment moderation, business native publishing or advertiser report is performed by this connection. See [post insights](https://business-api.tiktok.com/portal/docs/get-post-data-of-a-tiktok-account/v1.3).

### Account report API and durable feedback

`GET /api/reports/accounts`, `GET /api/reports/accounts/{id}`, `/history` and `/export` require `analytics:read` and are organization scoped. History supports `limit`/`offset`. `POST /api/reports/accounts/{id}/refresh` requires `analytics:collect` and has a one-minute per-account cooldown. Agent collection obeys the organization autonomy policy; managed action `report.refresh` uses the connection ID as `target_id` and supports the existing approval mechanism.

Successful snapshots, request intents and safe collection errors are persisted as audit events. A collection error retains the last successful snapshot. A connection changed during collection rejects that result. JSON export contains saved reporting data and collection/coverage semantics, never credentials or signed media URLs. Snapshot schema version 1 consists of `normalized`, `semantics`, optional `window`, `notice`, `context`, `coverage` and named `tables` with bounded rows. These reports provide durable agent context and export feedback; they do not create campaign publication records or automatically write GitHub. Reporting-only connections are excluded from campaign destinations in both UI and API.

## TikTok personal / Login Kit (Gate 15)

Configure `TIKTOK_CLIENT_KEY` and `TIKTOK_CLIENT_SECRET`, enable Login Kit and Content Posting API's upload product, and register `PUBLIC_URL/api/connections/oauth/tiktok/callback` as a static HTTPS redirect. Consent requests `user.info.basic`, `user.info.profile`, `video.list` and `video.upload`. [Login Kit](https://developers.tiktok.com/doc/login-kit-web) supplies creator identity; [renewal grants](https://developers.tiktok.com/doc/oauth-user-access-token-management) are encrypted and serialized because refresh tokens can rotate. TikTok for Business uses a separate authorization/reporting gate.

This initial personal integration uses [Upload to TikTok inbox](https://developers.tiktok.com/doc/content-posting-api-reference-upload-video). Review the current creator and video preview, explicitly consent, then start delivery from an owner session. Agent keys may prepare drafts and read outcomes but cannot initiate inbox transfers. One MP4 up to 80 MiB is supported. Post Chief parses the MP4 movie header to enforce the ten-minute upload limit; TikTok applies additional codec, frame-rate and dimension requirements and lets creators trim further to their account's duration limit.

Post Chief hosts assets, so it uses `PULL_FROM_URL`, with two-hour signed media access, rather than sending server-hosted content as a device upload. The owner must verify the final HTTPS media domain or `/api/media/` prefix in TikTok's developer app. See the [media transfer contract](https://developers.tiktok.com/doc/content-posting-api-media-transfer-guide). No app verification or live transfer has been performed during implementation.

Caption text remains editable and is shown for use in TikTok; the inbox upload API does not apply Post Chief's caption. Complete caption, visibility, interaction permissions, disclosures and posting in TikTok. Direct Post is outside this initial path; its [required export controls and client audit](https://developers.tiktok.com/doc/content-sharing-guidelines) are separate requirements, including restrictions on private/internal utility applications.

The worker saves a transfer intent before initialization and persists the returned task ID before polling. An uncertain initialization requires owner reconciliation instead of sending duplicate inbox notifications. [Status polling](https://developers.tiktok.com/doc/content-posting-api-reference-get-video-status) distinguishes download/processing, inbox delivery and completed native posting. `SEND_TO_USER_INBOX` becomes `awaiting_owner`, with no automatic repost or continuous polling. After completing the native post, choose **Refresh TikTok completion**; the worker checks the same task. `PUBLISH_COMPLETE` is required for a published outcome. Public video IDs are retained when available; completion without one retains its task ID and reports visibility/counters as unavailable. No public post is inferred from an inbox notification.

The [Display API video query](https://developers.tiktok.com/doc/tiktok-api-v2-video-query) supplies public video views, likes, comments and shares as native counters. Private/unavailable videos keep missing counters unavailable. Task status, creator and delivery metadata flow into dashboard/API and reviewed GitHub feedback. Final owner acceptance covers consent, verified media URL, reviewed transfer, native completion, status refresh and native metrics.

## YouTube (Gate 14)

Configure a Google **Web application** OAuth client as `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. Enable YouTube Data API v3 and YouTube Analytics API in that project. Register the exact `PUBLIC_URL/api/connections/oauth/youtube/callback` redirect and the final HTTPS application origin. Add the owner as a test user while consent is in testing. Start consent from Connections and choose the intended channel or Brand Account. Post Chief requires one existing channel from `channels.list(mine=true)` and stores its stable channel ID; it does not guess between multiple channels. Offline consent supplies a refresh grant, encrypted and renewed under the durable account lock.

Requested scopes are `https://www.googleapis.com/auth/youtube.upload`, `https://www.googleapis.com/auth/youtube.readonly` and `https://www.googleapis.com/auth/yt-analytics.readonly`. Shared Google client configuration will also support later Google integrations, with separate consent grants and scopes for each service.

Choose one MP4 asset (current application cap: 80 MiB). Under YouTube provider overrides, set the optional video title (campaign title fallback, at most 100 characters), visibility and an explicit made-for-kids declaration. Visibility defaults to private; an unset audience declaration blocks delivery. Descriptions are capped at 5,000 UTF-8 bytes; titles/descriptions exclude angle brackets. Paused YouTube destinations also expose these controls. Category is currently People & Blogs (22); custom categories, tags, thumbnails, playlists, live streams and native metadata edits are outside this upload path.

The worker uses Google's [resumable upload protocol](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol). It encrypts and saves a fixed-origin upload session before sending bytes, checks accepted offsets before each bounded chunk, verifies the local video digest, persists the accepted video ID and polls processing. Lost chunk/final responses resume the same session. An expired session or ambiguous accepted video requires owner reconciliation instead of starting another upload. Session URLs and tokens never appear in feedback, audit metadata or browser responses.

Delivery confirms the video's channel, processing and actual visibility. [Unverified API projects can be restricted to private uploads](https://developers.google.com/youtube/v3/docs/videos/insert). A public/unlisted request returned as private is a review/reconciliation outcome with a link to the existing video, not a successful public delivery. Dashboard/API and reviewed GitHub feedback retain actual/requested visibility and processing status. A known accepted video blocks a not-published reset, preventing creation of another video simply because the original is private.

Native Data API views, likes and comments are lifetime counters. Separate Analytics shares and watch time use a requested 30-day window in [YouTube's Pacific reporting dates](https://developers.google.com/youtube/analytics/dimensions#time-periods), which can lag. Watch time is normalized to seconds; raw estimated minutes and the requested date window remain available. If the separate Analytics report fails or has no row, valid lifetime counters are retained and missing window counters stay unavailable. Live channel consent, a reviewed upload, processing/visibility checks and native reporting remain for the final owner pass.

## Bluesky (Gate 4)

Connect with a handle and an App Password using the Connections API. Post Chief stores encrypted session and refresh tokens, not the password. Reconnecting preserves the account ID and publication history. This release supports Bluesky-hosted PDS domains (`bsky.social` and subdomains of `bsky.network`); other federated PDS hosts require an explicit future connection policy.

Text uses the [post lexicon](https://github.com/bluesky-social/atproto/blob/main/lexicons/app/bsky/feed/post.json): at most 300 grapheme clusters and 3000 UTF-8 bytes. Links use UTF-8 byte offsets in facets. Images use the [image embed lexicon](https://github.com/bluesky-social/atproto/blob/main/lexicons/app/bsky/embed/images.json): at most four raster images, each at most 2,000,000 bytes. SVG must be rasterized before publishing.

MP4 videos are uploaded through the video service with a PDS-scoped service token. The adapter returns a pending state while the [video job](https://github.com/bluesky-social/atproto/blob/main/lexicons/app/bsky/video/defs.json) processes; the scheduler persists and resumes that job rather than reuploading. Post Chief's application upload limit is 80 MiB, lower than the provider's current maximum.

Each publication gets a stable repository record key in the [TID syntax required by feed posts](https://atproto.com/specs/record-key). It encodes a digest of the publication ID; actual publication time is stored in `createdAt`. Before writing, the adapter checks that key; an existing record is reconciled as the same publication. Writes use compare-and-swap creation through [putRecord](https://github.com/bluesky-social/atproto/blob/main/lexicons/com/atproto/repo/putRecord.json), preserving existing posts. Session refresh updates the encrypted credentials through the calling publication worker.

Analytics reports supported engagement counters. Missing counters and unsupported impressions are not invented. Comments and replies are not advertised in this MVP adapter.

Live connection and publication still require the owner's Bluesky account and intended content. Local HTTP contract tests verify requests and recovery behavior; they do not prove live provider access.

## Pinterest (expanded Gate 13)

Configure `PINTEREST_CLIENT_ID` and `PINTEREST_CLIENT_SECRET`; register the exact callback `PUBLIC_URL/api/connections/oauth/pinterest/callback`. Consent requests `boards:read,pins:read,pins:write,user_accounts:read`. Encrypted continuous refresh tokens use a durable renewal intent shared by publishing, analytics and board discovery. Unconfirmed renewal requires reconnecting rather than reusing a possibly rotated token.

After connecting, choose an accessible public board in Connections. Discovery is paginated. Switching an already selected board is blocked while pending drafts/deliveries exist; an initially missing board can be configured to recover setup errors. Reconnecting requires choosing the board again. A publication retains its board ID in its encrypted public-write intent.

The initial adapter publishes one JPEG/PNG image up to the 10 MB application cap, with a description up to 800 characters and asset alt text up to 500. Images are sent as Base64. Video, carousel, board creation, custom Pin titles/links and native Pin edits are not implemented in this first pass. Text-only campaigns are rejected for Pinterest. Scheduling, independent outcomes, permalinks, reconciliation and reviewed feedback use the existing paths.

Pin analytics cover the last 30 UTC days. Impressions and outbound clicks preserve that window; Pin clicks and saves remain in provider data. Missing counters remain unavailable. App access, permissions, consent and intended live Pin acceptance remain for the final owner pass. Sources: [Pinterest OpenAPI](https://github.com/pinterest/api-description) and [authorization guide](https://developers.pinterest.com/docs/getting-started/set-up-authentication-and-authorization/).

## X (core foundation)

### Handoff without API credits

Saved campaigns expose **X · manual handoff** under Delivery even without X credentials. Copy the platform-specific caption, download selected JPEG/PNG/WebP images, post in X and record the URL and actual publication time. The record is explicitly owner-reported, is never dispatched by workers and has no native analytics collection. Existing automated publication outcomes are unchanged. The record and unavailable metrics flow into the same reviewed GitHub feedback. One campaign cannot use both direct and manual X delivery. See [final-pass instructions and limitations](mvp-final-pass.md).

### Direct API integration


The owner's core networks are Facebook, Instagram, Threads and X. Bluesky and LinkedIn remain optional follow-ups. X live account acceptance has not been performed.

Configure `X_CLIENT_ID` and `X_CLIENT_SECRET` with the **OAuth 2.0** credentials for a confidential Web App in the X Developer Console. These are not the API key/secret or an app-only bearer token. Enable user authentication and register the exact callback `PUBLIC_URL/api/connections/oauth/x/callback`, plus the dashboard website URL. Start consent with **Connect X** in Connections. Requested scopes are `tweet.read tweet.write users.read media.write offline.access`. State is owner/organization-bound, expires after ten minutes and is single-use. PKCE uses S256 with a server-keyed verifier derived for each random state; token exchange uses HTTP Basic client authentication. Tokens stay encrypted on the server.

X API requests use paid credits. Review credits and a spending limit in the Developer Console before live use; Post Chief does not purchase credits or change billing. X analytics collection is **manual** through Request fresh metrics: successful or non-transient failed reads stop until another request. Transient failures retain the normal retry deadline. Public metrics include reported likes, replies, reposts and impressions when available; missing fields remain unavailable. Reposts retain their meaning in provider metrics.

This adapter supports ordinary posts with text and up to four JPEG, PNG or WebP images, each at most 5 MB. Text validation uses a conservative weighted bound of 280: long URLs and complex emoji can be overcounted. A provider override can shorten X copy without changing other destinations. Videos, GIFs, long posts, replies, quote posts, native text edits and image alt-text metadata are not implemented in this first pass. Each image ID and expiry is persisted before publication intent. Expired uploads require review; upload acceptance does not establish public publication.

X posts use the existing scheduler, independent destination outcomes and owner reconciliation. A lost public-write response requires checking X before retrying. Successful posts retain the returned numeric ID and a public status link for feedback. Rotating refresh grants use a durable encrypted account intent and conditional save before other provider work. Concurrent jobs wait through retry; interrupted or unconfirmed renewal requires reconnecting, rather than reusing a possibly consumed refresh token. Successful renewed credentials are stored before media or public I/O.

Official contracts: [OAuth PKCE](https://docs.x.com/fundamentals/authentication/oauth-2-0/user-access-token), [create posts](https://docs.x.com/x-api/posts/create-post), [media upload](https://docs.x.com/x-api/media/upload-media), [post lookup](https://docs.x.com/x-api/posts/get-post-by-id), [pricing](https://docs.x.com/x-api/getting-started/pricing).

## Meta connections (Gate 5)

Configure `META_CLIENT_ID`, `META_CLIENT_SECRET`, and `META_API_VERSION` for a Facebook App using Facebook Login. The owner authorizes Pages; linked professional Instagram accounts are discovered from those Pages. Consumer Instagram accounts are unsupported. Threads requires the Access the Threads API use case and its own **Threads App ID/secret**, configured as `THREADS_CLIENT_ID` and `THREADS_CLIENT_SECRET`; Facebook Login credentials are not interchangeable. A separate developer app registration is recommended for this setup. If Meta offers the Threads use case on the existing registration, its Threads-specific credentials can also be used: Post Chief does not require the two registrations to be separate. Both connections use the same Post Chief dashboard.

Register exact callbacks at `PUBLIC_URL/api/connections/oauth/meta/callback` and `PUBLIC_URL/api/connections/oauth/threads/callback`. Start with an authenticated, CSRF-protected POST to `/api/connections/oauth/{provider}/authorize`, then open the returned URL. State expires after ten minutes, is bound to the owner and organization, and is atomically consumed before exchange. Tokens are encrypted and never returned to the browser. App review and the required permissions must be available for accounts outside app roles.

The Threads connection requests `threads_basic`, `threads_content_publish` and `threads_manage_insights` for profile/post access, publishing and analytics. Enable those permissions in the Threads use case before connecting. Use the Threads-specific callback above; the Facebook/Instagram callback does not handle Threads consent.

Threads callback failures identify whether the authorization-code exchange, long-lived token exchange or profile lookup failed, with numeric provider codes when available. Provider response text and tokens are not displayed. The normalized `AUTH_REVOKED` reason does not by itself establish that the owner revoked access. Start each retry from Connections: callback state is single-use even when an exchange fails, and refreshing an old callback cannot retry consent.

The long-lived Threads exchange sends the short token as the `access_token` query parameter, matching [Meta's official sample](https://github.com/fbsamples/threads_api/blob/main/src/index.js). Profile requests continue to use bearer authentication. Keep exchange request URLs out of logs because they contain credentials.

Both the Facebook and Instagram dashboard buttons currently use the combined Meta consent flow. Its requested scopes are `business_management`, `pages_show_list`, `pages_read_engagement`, `pages_read_user_content`, `pages_manage_posts`, `instagram_basic`, `instagram_content_publish` and `instagram_manage_insights`. The Instagram setup's required-content button alone may not enable Page publishing or Instagram insights. In the Instagram use case, open Permissions and features and add `instagram_manage_insights`. Add the Content management use case **Manage everything on your Page**, customize it, and enable `pages_manage_posts` in its permission table before connecting. An `Invalid Scopes` error naming `pages_manage_posts` or `instagram_manage_insights` means the app configuration must be checked for those permissions; retrying the same authorization URL will not add them. Register the exact tunnel hostname under App Domains too, and update it and the redirect URI if the Quick Tunnel hostname changes.

Facebook reactions and comments summaries also require `pages_read_user_content`; add it in the Page use case permission table and start fresh consent after enabling it. Existing publication records are retained on reconnection; reauthorization does not republish campaigns.

Meta configuration failures can redirect back with `error_code` and no state. Post Chief returns a fixed diagnostic and never exchanges a code or creates a connection for such a callback. Successful callbacks still require valid, single-use actor-bound state. Start a fresh connection from Connections after correcting the provider configuration.

Facebook supports text, raster photos and MP4 Reels; Instagram supports JPEG images, MP4 Reels and carousels (application cap: ten items); Threads supports text, images, video and carousels (twenty items). Application media size is capped at 80 MiB. Media URLs for Instagram, Threads and hosted Facebook Reels require public HTTPS. Platform encoding, dimensions, duration and permission checks can still reject media. File acceptance alone does not prove platform eligibility.

Provider preparation returns persisted checkpoints. Public mutations require a saved `publish_intent` before execution. These providers have no application idempotency key: an uncertain response or recovery at that intent requires reconciliation. Do not blindly retry and risk duplicate posts. Facebook Reels wait for the publishing phase to complete. Instagram and Threads reuse stored containers and poll processing status. Threads long-lived tokens support refresh while unexpired; revoked or expired connections require owner reconnection.

Implementation follows Meta's official [Facebook collection](https://www.postman.com/meta/facebook/documentation/r56bjfd/facebook-api), [Instagram collection](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api), and [Threads collection](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api). Live account acceptance remains a separate gate check requiring the owner's configured apps and consent.

### Maintaining an existing campaign

After delivery, owners can add another connected destination without resetting existing publications. The new destination stays paused until explicitly scheduled or published. Its provider copy and media can be edited while paused and unattempted. Shared copy for an existing provider cannot be changed through this action. Existing publication IDs, timestamps, attempts, analytics and original master copy are retained. These maintenance endpoints currently require an owner session.

Published Facebook feed post text can be updated using **Edit Facebook text**. Load current native text, change it, review before/after, then apply that exact review. Reviews expire after ten minutes, are owner/publication-bound and single-use, and reject a changed remote caption. Post media is retained. Edit intent and result are recorded separately in the publication's feedback history. Unconfirmed edits require loading and verifying current native text before another edit; they are never retried automatically. Facebook has no conditional text-update API, so a native edit between the final read and update can still conflict.

Meta's [Facebook Post SDK](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/post.py) exposes the `message` update parameter. Its [Instagram Media SDK](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/igmedia.py) does not expose caption updates. Instagram captions must therefore be changed through the **Edit on Instagram** link. Changing published media or editing other post formats is not implemented; this flow never deletes and recreates a post.
## Google Business Profile (Gate 17)

Provider key `gbp` reuses `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`, with a separate exact callback `PUBLIC_URL/api/connections/oauth/gbp/callback` and `https://www.googleapis.com/auth/business.manage` consent. Configure a confidential Google web OAuth client and obtain Business Profile API project access. Enable Account Management, Business Information, Business Profile Performance and the Google My Business v4 API used by local posts. Google project approval, location ownership/management, verification and content eligibility remain owner setup requirements; connecting successfully does not guarantee local post eligibility.

Consent discovers accessible accounts and locations using fixed Google endpoints and required location field masks. It connects each unique location, bounded to 20 accounts and 100 total locations; excess discovery fails explicitly rather than silently hiding destinations. Select the intended location in the campaign editor. Its `accounts/{accountId}/locations/{locationId}` identity is displayed to distinguish similarly named locations. Reconnect to discover newly granted locations. Credential renewal is encrypted and serialized through the shared durable account intent.

MVP delivery creates `STANDARD` local posts with English (`en-US`) copy of 1–1,500 characters and at most one JPEG/PNG image, 10 KiB–5 MiB, at least 250 × 250 pixels. Google fetches the signed public HTTPS media URL. Events, offers, CTA configuration, native editing/deletion and business profile edits are outside this initial local-post path. Existing campaign scheduling, provider overrides and adding a destination use the same location adapter.

The worker persists a write intent before creation and saves the accepted full post resource before reading status. `PROCESSING` remains pending; only `LIVE` is published. Rejection or unknown state retains the accepted resource and requires review/reconciliation. A lost create response or interrupted public write requires reconciliation; retries never recreate an already accepted resource. Reconciliation validates the full post name against the connected location and blocks a not-published retry when Google already confirmed acceptance. Google Search URLs are accepted only from fixed Google HTTPS hosts.

Post insight reads request Search views and call-to-action clicks for the last 30 UTC timestamp days; returned timezone and reporting lag accompany snapshots. Missing legacy insight values remain unavailable. These counters flow through existing campaign analytics and reviewed GitHub feedback. Location performance uses the separate shared account-report endpoints `/api/reports/accounts/{id}` (latest, history, export and refresh), existing `analytics:read`/`analytics:collect` scopes and managed agent `report.refresh`. Snapshots are durable and organization scoped; failed collection retains the latest successful report. No automatic social-workspace write occurs.

Daily location reports request seven native performance metrics over 30 complete dates selected relative to UTC: desktop/mobile Search and Maps impressions, direction requests, call clicks and website clicks. Google defines the location reporting dates; no UTC location timezone is invented. Surface impressions are unique per day and surface, so they are not summed into unique reach. A returned daily `DatedValue` with omitted value is native zero under Google's contract; missing dates/metrics remain unavailable. The table preserves separate metric/date rows with requested window and coverage.

Official contracts: [location discovery](https://developers.google.com/my-business/reference/businessinformation/rest/v1/accounts.locations/list), [local posts](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.localPosts), [post insights](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.localPosts/reportInsights), [daily performance](https://developers.google.com/my-business/reference/performance/rest/v1/locations/fetchMultiDailyMetricsTimeSeries), [daily zero semantics](https://developers.google.com/my-business/reference/performance/rest/v1/TimeSeries), [photo requirements](https://support.google.com/business/answer/6103862).
## Web analytics and blog sources (Gate 18)

`web` is a read-only GA4 reporting connection. Reuse the confidential Google web client, enable Analytics Admin and Data APIs, and register `PUBLIC_URL/api/connections/oauth/web/callback`. Consent requests only `https://www.googleapis.com/auth/analytics.readonly`; it discovers up to 100 accessible properties over five account-summary pages. Each property becomes a reporting connection, never a campaign destination. Tracking must already be installed. No tags, property settings or website content are written.

The adapter reads the property's IANA timezone and freezes a concrete 30-complete-day window before requesting native totals, daily activity (30 rows) and session channels (25 rows). Metrics are active users, sessions and page/screen views. Property totals are requested separately; daily/channel active users are never summed into unique window users. Missing rows remain unavailable. Saved coverage includes native row counts, truncation and threshold/data-loss flags; native data can lag. GA4 properties that also contain app streams report page/screen activity according to Google's metric meaning, not an invented website-only count. [Admin account summaries](https://developers.google.com/analytics/devguides/config/admin/v1/rest/v1beta/accountSummaries/list), [Data API reports](https://developers.google.com/analytics/devguides/reporting/data/v1/rest/v1beta/properties/runReport).

`blog` is a public RSS 2.0/Atom source connection. In Connections, enter a website and discover advertised alternate feed links, or connect a direct feed URL. Discovery suggests at most ten links; connecting validates the selected feed. Saved snapshots include up to 100 entries with bounded plain-text titles/summaries, provider date text and entry IDs. The native source is explicitly untrusted external context: feed contents cannot authorize actions or become agent instructions. No article pages, remote images or attachments are fetched, and no publication outcomes/counters are invented.

Fetches require HTTPS, default port, no userinfo/fragments, only public DNS results and an available IPv4 address. The reader pins each connection to a checked public IPv4 address while preserving the original Host/TLS hostname, disables environment proxies and redirects, then explicitly revalidates each of at most three redirects. Each document is limited to 1 MiB with a 30-second total deadline, uncompressed responses and no XML DTD/entities/UTF-16. Website HTML discovery requires UTF-8. IPv6-only feeds, authenticated feeds, private networks, arbitrary attachment downloads and blog publishing are outside this MVP path. Redirect/feed candidates do not grant permissions or connect themselves.

Owner endpoints: `POST /api/connections/blog/discover` and `POST /api/connections/blog`, each accepting `{url}` under existing owner/CSRF protection. Collection uses shared scoped account reports/history/JSON export and managed agent `report.refresh`; `analytics:read` exposes saved source snapshots and `analytics:collect` governs fresh collection. Encrypted source configuration and a connection nonce prevent a reconnect/disconnect during collection from saving stale results. A failed refresh retains the last successful snapshot. Account reports provide durable API/agent context and exports, without automatic social-workspace writes.
## Twitch (Gate 19)

Set `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET` for a confidential Twitch application, with exact redirect `PUBLIC_URL/api/connections/oauth/twitch/callback`. Owner authorization-code consent requests `moderator:read:followers` for follower totals. Tokens are encrypted; code exchange and renewal validate the configured client ID, granted scope and user identity against Twitch's fixed validation endpoint. No email, stream-key, channel-edit, chat, subscription or broadcast-write permission is requested. Reconnection preserves existing snapshots.

Reports expose channel/profile context, the actual follower total, current concurrent viewers only when Twitch returns a live stream, and up to 20 recent videos with lifetime native view counts. Offline status does not establish zero historical viewers. Optional follower/video failures remain explicit in saved coverage while valid channel/live context is retained. Individual follower records, email addresses, video bytes and remote thumbnails are not retained/downloaded. Historical broadcaster audience analytics, Twitch game/extension analytics and feed-style publishing are outside this channel connector.

Twitch is reporting-only: collect snapshots in Analytics, inspect history/coverage or export scoped JSON, and use existing agent `report.refresh` with `analytics:collect` plus saved reads under `analytics:read`. Connections cannot become campaign destinations. The worker enqueues validation at startup; the scheduler checks due grants every minute and validates maintained grants every 50 minutes. Invalid authorization or scope disconnects the matching encrypted grant without invalidating a concurrent owner reconnection. Temporary provider failures retain the connection and produce an audit diagnostic. Keep the worker and scheduler running for maintained Twitch sessions. Every actual report collection additionally validates its token before native reads.

Official sources: [authorization-code grants](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/), [token validation requirement](https://dev.twitch.tv/docs/authentication/validate-tokens/), [refreshing grants](https://dev.twitch.tv/docs/authentication/refresh-tokens/), [Helix channel/stream/video reference](https://dev.twitch.tv/docs/api/reference).
